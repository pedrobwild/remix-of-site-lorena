# src/lib

- Direct Google Ads delivery uses event-scoped private callback capabilities, a transactional queue and existing actions; activation requires disabled duplicate imports, current cookie proof and GCLID. Accepted ingestion is not attribution.

- Qualified-objective reports use admin-authorized paginated reads and canonical offline row building; return aggregates and hashed CSV only, keeping dashboard counts distinct from exportable conversions.

- Home search metadata and keywords share homeSeo exports between SSR and the client hook; preserve admin overrides to avoid divergent tags after hydration.
- Reform service routes and client SEO hooks share title, description and keyword exports from their content modules; compact-apartment queries belong to the studio service URL, avoiding competing duplicate pages.

- Folhas `.bwa` (`home-bwa.css` + `bwa-internal.css`) saem no HTML do servidor pelo `seoHead()` e pelo `BwaNav` (mesmo recurso, grupo de precedência `bwa` = últimas do `<head>`); `keepBwaStylesheetsLast` só as move numa navegação interna, quando o CSS da página nova entrou depois. O `<link>` do BwaNav segura a troca de página até a folha carregar, então `installBwaStylesheetPreinit` (Root) já as pede no início da navegação (`onBeforeNavigate` + `preinit` do React) — sem isso o primeiro clique a partir da home esperava uma ida e volta de rede a mais. Tudo em `src/lib/bwaStylesheetOrder.ts`.

- Velocidade (25/10/2026): a hospedagem da Lovable reescreve o `Cache-Control` do HTML para `no-cache`, não guarda HTML na CDN, a Cache API do worker não persiste (`x-bw-edge: MISS` sempre, medido após publicar) e, com páginas pré-renderizadas no build (testado em 25/10/2026 e removido), só o `/index.html` da raiz era servido como estático — as demais caíam no SSR, e a tentativa de ler o arquivo pelo binding `ASSETS` custava 500–1.000 ms por visita. Não reintroduzir prerender sem confirmar que a hospedagem serve `<rota>/index.html`. Por isso o que faz diferença é o servidor não ir ao banco a cada visita: `get_public_site_settings` passa por `readPublicSiteSettings` (memo de 60 s, `src/lib/siteSettingsServer.ts`; não chamar o RPC direto nas funções de servidor) e os loaders de conteúdo (lista de projetos → links de bairro, lista de posts, artigo e projeto por slug, FAQ) passam por `serverMemo` (`src/lib/serverMemo.ts`: só no servidor, só resultado bom, 60 s — teto de atraso para uma edição no painel aparecer no HTML; o navegador continua buscando ao vivo). Medido: /orcamento sem ida ao banco responde em ~80–110 ms; com uma ida, 900–1.300 ms. O cache de borda (`src/lib/edgeHtmlCache.ts`) fica no código, inofensivo, para quando a hospedagem passar a ter Cache API de verdade. Endereço antigo `/<slug>` de artigo ou projeto publicado responde 301 para `/conteudos/<slug>` ou `/portfolio/<slug>` (`legacyContentPath`).
