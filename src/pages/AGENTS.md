# src/pages — home, CSS e velocidade

- The Interested leads tab reuses the existing protected lead page and paginated records; its read-only contact list uses shared safe contact links and São Paulo timestamps without duplicating storage or changing qualification workflows.
- Home acima/abaixo da dobra (25/10/2026, terceira rodada): a rota "/" carrega no `<head>` só `src/pages/home-critical.css` (parte de `home-bwa.css` que a primeira tela usa: tokens, base, cabeçalho, menu mobile, hero, barra fixa do celular — ~24 KB / 6 KB gzip) e pré-carrega `home-deferred.css`, cujo `<link>` entra no CORPO da home logo antes da primeira seção depois do hero (`withDeferredStylesheet` em `home-bwa-body.ts`; marca `HOME_FOLD_MARKER` = `<section class="bwa-audience"`): o navegador pinta cabeçalho e hero sem esperar e só segura o que vem depois do link. Os dois arquivos são DERIVADOS de `home-bwa.css` pelo mesmo plugin (`scripts/bwaShell.ts`, `buildHomeSplit`): classe presente no HTML até o fim do hero → crítico; o adiado leva o resto E repete as críticas que também alcançam elementos de baixo (`.bwa-title`, `.bwa-lead`, `body`…), na ordem original — sem isso a cascata mudava (peso do `.bwa-services-title`, cor do `.bwa-lead`). Verificado com diff de estilos computados (todas as propriedades, ::before/::after, 3 larguras, menus abertos): zero diferenças. Nunca editar os gerados; mover o hero ou a marca da dobra exige rever `FOLD_END_MARKER`/`HOME_FOLD_MARKER` (teste `bwaShell.test.ts`).
- CSS que bloqueia a renderização (25/10/2026, segunda rodada): (1) `src/index.css` foi auditado seletor a seletor em 51 páginas públicas e caiu de 168 KB para 24 KB — a home antiga, ensaios, portfólio/projeto antigos, blog antigo e página Sobre não existem mais; o que era do painel foi para `src/styles/admin-legacy.css`. (2) Folhas do painel (`admin-legacy.css`, `admin-font-scope.css`) entram SÓ pelo `AdminChunk`, como `<link precedence="admin">` a partir de `?url`; um `import "…css"` em `ProtectedRoute`/`AdminLayout` cai no chunk compartilhado `index-*.css`, que toda página pública carrega (era assim: `[class^="admin-"] *` estava no CSS da home). (3) As páginas internas carregam `src/pages/bwa-shell.css` no lugar de `home-bwa.css`: é a parte de `home-bwa.css` que alguma página interna usa, DERIVADA no build pelo plugin de `scripts/bwaShell.ts` (regra: classe que aparece em algum arquivo de src fora da lista `HOME_FILES` → shell; na mesma ordem do original, então a cascata não muda). Nunca editar `bwa-shell.css` à mão nem importar `home-bwa.css?url` fora de `src/routes/index.tsx` (`bwaShell.test.ts`). Classe nova usada numa página interna precisa aparecer literalmente em algum .ts/.tsx fora da home (não montada por template string) para a regra ir ao shell. Resultado em /orcamento: CSS bloqueante de ~60 KB gzip para ~30 KB.
- Home section images use the source-controlled responsive HOME_SLIDES variants; retain public originals for existing metadata and other pages to preserve stable URLs. Initial-route parsers use lightValidators to avoid importing the full form-validation library. Google tags share one deferred loader with current-consent and non-admin checks at execution; configuration and conversion calls keep the existing queue. Neighborhood headings reuse noBairro/bairroPreposicao; article-only service linking runs after sanitization in SSR and browser, never on license content. Never inline home CSS into route head because it enters every route's initial JavaScript.
- The root keeps CookieBanner eager to preserve immediate preference events; SiteAssistant loads through a hydration-gated Suspense boundary and maintenance assets load only when maintenance renders, avoiding unrelated CSS in the initial public graph.
- Desktop hero variants and their srcset/sizes are defined once in homeHero.ts and reused by picture and preload; this prevents duplicate image requests while preserving the original crop and mobile source.
- Core Web Vitals no celular (30/10/2026, PageSpeed: LCP 2,6 s no laboratório e 4,4 s no campo, "reprovado"): (1) a foto do hero é pré-carregada por `preloadHomeHero(preload)` no RENDER do HomePage (`src/content/homeHero.ts`) — o React escreve preload de imagem com `fetchPriority="high"` logo após charset/viewport, antes das folhas e dos ~40 `modulepreload`; nunca devolver esse preload ao `head()` da rota (lá ele sai no fim do `<head>`). (2) Página carregada a partir do `__root.tsx` (NotFoundPage) não importa CSS (`import "x.css"`): o CSS iria para a folha do root, que bloqueia a renderização de TODA página; use `?url` + `preinit(url, { as: "style", precedence })` do react-dom (no servidor sobe para o <head>; no navegador NÃO suspende — um `<link precedence>` deixava /reforma/:slug e /portfolio/:slug em branco ao trocar o esqueleto pela 404). (3) `home-deferred.css` só bloqueia a partir de 901 px (`HOME_DEFERRED_BLOCKING_MEDIA`, onde o topo de `.bwa-audience` aparece na primeira tela); abaixo disso entra com `media="print"` + `onload` (que troca para `HOME_DEFERRED_ASYNC_MEDIA`, o complemento exato — as duas cópias nunca valem juntas), `<noscript>` e a rede de segurança `activateDeferredStylesheet` no HomePage. (4) A entrada suave (`installReveal`) só esconde o que está abaixo da tela na montagem (IntersectionObserver de triagem), para não apagar o que já foi pintado (Speed Index). (5) Medições iniciais de layout na montagem da home vão para `requestAnimationFrame` (reflow forçado). (6) O botão "Dúvidas" sobe por `transform`, nunca animando `bottom` (cada quadro contava como CLS). (7) `sizes` das fotos da home = largura real do bloco. Guardado por `src/__tests__/mobileCwv.test.tsx`, `bwaShell.test.ts` e `homeBwaScript.test.ts`.
